# 下一步接口需求

本轮已有一个 Controller 状态、一个领域地图、Corpus、Search Ledger、Evidence Registry 和 Evidence Card 集合。后续模块沿这套记录接入，不另建并行科研工作流。下列为实现需求，不是已实现接口。

| 接入点 | 输入／输出需求 | 当前可复用入口 |
| --- | --- | --- |
| 领域认知交接 | 当前地图、覆盖判断、来源策略、Corpus／Ledger／Registry 的路径及哈希；按稳定 Evidence ID 取原文定位和主张边界 | `literature-handoff` |
| 两类问题发现 | 核心应用与目标、领域公认难题或主动发现的共性 failure、依据、重要性、现有解决程度、未验证判断、强 prior 后追问与反例 | 当前有效科研要求；地图和 Evidence；尚未实现候选生成 |
| 人工选择问题 | 候选集合及其依据、用户明确选择、核心问题与版本、允许调整的条件；不由调研覆盖判断替代人工选择 | 尚未实现新的选择记录与问题版本接口 |
| 问题／方法知识缺口 | 调研请求来源、核心应用、问题 ID／版本、路线版本、具体缺口和关闭条件；返回更新后的地图及证据，继续原科研工作 | `update-literature --requested-by ... --context ...`；当前 context 仅留存，不验证尚未实现的问题／路线对象 |
| 可调整技术主线 | 具体技术路线、成熟方法来源、复用／迁移／改造范围、输入输出、机制匹配、假设、关键推导、备选及修改依据 | 保留的来源与证据链；尚未实现方法产物及路线状态 |
| 贡献检查与验证 | 本领域 prior 的实质覆盖程度、外域成熟方法的迁移机会、理论／实验检查、反例、独立验证、主张及条件；结果应能改变设计或返回问题发现 | 现有调研与按缺口更新；尚未实现统一设计／验证循环 |
| 反馈与版本 | 哪个判断发生变化、依据、受影响问题／路线／地图版本、人工决定及回到哪里 | 现有地图历史和更新请求；后续按实际需要接入版本、反馈消费 |
| ARS／Nature 能力 | 追问、质疑、跨域术语、机制逆向分析、组件与假设、工程验证；产物绑定同一科研对象和 Evidence | 本轮只确定选择性复用方向，尚未安装或调用它们的 workflow |

旧 kernel 的 phase-scoped incremental literature、版本和反馈实现作为复用材料保留。其旧 phase 与 RCA／Principle anchors 不能直接成为新的问题／方法入口契约；下一步需要围绕已选问题和具体技术路线调整绑定。当前按缺口更新会修订并重新检查领域地图，适合本轮的独立调研入口。

后续验收需要实际案例：看强 prior 后是否持续发现重要痛点、两类 prior 是否正确处置、核心问题是否保持、是否形成有真实推导与验证的完整方法。当前工程测试不证明这些科研效果，不能宣称已稳定产出顶会顶刊方法。
