# JSON payload contracts

All fields below are required unless marked optional. Strings must be nonempty; lists have entries unless explicitly allowed empty. Evidence IDs name current accepted cards in the same run. Immutable version bindings come from `science status` or `handoff`; never construct hashes from memory. The executable validators live in `harness/scientific_validators.py` in the source checkout.

`frame.json`: core_application, key_research_question, target_domain, operating_envelope (strings); success_criteria and constraints (string lists).

`problems.json`: candidates (objects), feedback_responses (may empty). Each candidate: id, core_application, key_research_question, pain_point, significance, current_solution_extent, scope_change_rationale; discovery_path COMMUNITY_RECOGNIZED or COMMON_FAILURE; failure_origin AUTHOR_REPORTED, INFERENCE or HYPOTHESIS; evidence_ids; interrogation {strongest_argument, premises[], counterexamples[], alternative_explanations[], literature_conflicts[] (may empty), first_principles (required for COMMON_FAILURE)}; prior_assessments; unverified_claims[] (may empty). COMMON_FAILURE needs at least two paper Evidence IDs. Preserve core_application. A packet declaring covering in-field prior needs followup_gaps[] and automatically returns through map update and important-pain discovery.

Prior: evidence_ids[], source_domain, domain_identity IN_FIELD/CROSS_FIELD/UNCERTAIN, domain_rationale, coverage SUBSTANTIAL/PARTIAL/RELATED/UNKNOWN, covers PROBLEM/CONTRIBUTION, coverage_rationale, strongest_argument, assumptions, failure_boundaries, remaining_pain. `prior.json`: prior_assessments, problem_binding if a problem is selected, followup_gaps[] when in-field substantial coverage exists.

Feedback response: feedback_id, response, changed_elements (string), evidence_ids[] (may empty). Include exactly every pending item for the submission's stage. Explain justified disagreement rather than mechanically accepting every request.

`method.json`: problem_binding {problem_id, version, sha256}; route_id, change_reason, scientific_delta, expected_benefit; design_mode DIRECT_REUSE/TRANSFER/ADAPT/FUSE/ORIGINAL; original_design_rationale if ORIGINAL; mechanism; mature_method_search; prior_assessments[] (may empty); claims[]; checks[]; alternatives[]; improvements[] (optional); feedback_responses[]; followup_gaps[] if substantial in-field prior.

Mechanism: model, applicability; variables [{name, meaning, units}]; inputs[], outputs[]; algorithm [{id, operation, inputs[], outputs[]}]; derivations [{id, expression, rationale, assumptions[], status INFERENCE/CHECKED, check_ids[] when CHECKED}]; components [{id, purpose, input, output, why_needed, isolation_test, assumptions[]}]; assumptions[]. CHECKED derivations require performed passing THEORY results for the same problem and mechanism.

Mature search: queries [{query_id (an actual query_events ID), terms, domain, outcome}]; sources[] (may empty) [{evidence_ids[], domain_identity, domain_rationale, mechanism, input_output_match, assumption_match, reuse_mode DIRECT_REUSE/TRANSFER/ADAPT/FUSE/NOT_USED, changes, attribution, coverage, coverage_rationale}]. No modification volume or whole-problem isomorphism requirement.

Claim: id, statement, kind THEORETICAL/EMPIRICAL, evidence_status AUTHOR_REPORTED/INFERENCE/HYPOTHESIS/VALIDATED, evidence_ids[] (may empty), check_ids[] (may empty), limitations. VALIDATED requires an actual passing result for the exact claim, selected problem and unchanged technical mechanism; empirical claims need INDEPENDENT_VALIDATION, theoretical claims THEORY. Design trials never establish independent empirical contributions.

Check plan: check_id, kind THEORY/DESIGN_SELECTION/INDEPENDENT_VALIDATION, claim_ids[], comparison, controls, metric, setting, expected_observation, falsifying_result, execution_authorization; derivation_ids[] when theory checks support CHECKED derivations. Include at least one independent validation plan. Improvement: change, rationale, benefit, cost, validation, evidence_ids[] (may empty).

`result.json`: route_binding {route_id, version, sha256}, plan_sha256 (canonical SHA256 of the exact plan using sorted-key compact UTF-8 JSON), check_id, kind, claim_ids and derivation_ids (matching plan), outcome PASS/FAIL/INCONCLUSIVE, finding, design_consequence, independence_rationale, execution_authorization, evaluation_units[], artifacts [{path (inside research directory), sha256 (actual file bytes), origin}], action REVISE_METHOD/RETURN_TO_PROBLEM/UPDATE_LITERATURE, gaps[] for the last two actions. IDs are immutable. Independent and design trials cannot share units or result bytes. This tests declared separation; the reviewer must examine actual independence and scientific validity.

`update.json`: gaps[], requested_by field_cognition/problem_discovery/method_design, context {close_conditions[] optional, one per gap; optional scientific bindings must match current state}. The Controller supplies actual problem/route versions and application. Accepted coverage returns to the saved work with new feedback.

Review payload: run_id, review_request_id, reviewer (actual model), verdict_id, rationale, reviewed_artifact_hashes (exact request bindings), decision (one of request.accepted_verdicts), assessments {each requested dimension: {status PASS/GAP, rationale}}, issues[] [{id, target PROBLEM_DISCOVERY/METHOD_DESIGN (must match return stage), rationale, requested_change, evidence_ids[]}], prior_assessments[]; gaps[] for update, return or covering prior. READY requires all dimensions PASS and no unresolved issue/covering prior. Only the fresh role's exact Hook-attested JSON is accepted.
